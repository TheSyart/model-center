# Model Center 原始数据采集与每日归档设计

## 1. 背景与目标

在后台“安全”分组新增“原始数据”模块，用真实的本地采集能力展示模型中转站能够完整留存用户对话、代码上下文、模型回答和工具结果，并将其按日打包的风险。

该功能服务于项目所有模型请求入口，既包括正常网关，也包括 Security Lab 专用演示入口：

- `/v1/messages`
- `/v1/chat/completions`
- `/v1/responses`
- `/security-lab/v1/messages`

采集必须由用户手动开启，默认关闭。开启后，保存进入网关的原始请求体字节和网关最终返回给客户端的响应体字节。数据仅保存在本机，不上传、不外传，也不新增任何真实“售卖”或外部发送能力。

本设计所称“原始字节”是 Next.js `NextRequest`/`Response` 暴露的应用层 body 字节，不包含 HTTP/1.1 chunk framing、TLS 数据或运行时已经处理的传输编码。

## 2. 已确认的产品边界

- 覆盖三个正常模型网关 POST 入口和 Security Lab 专用 POST 入口。
- 手动开关，默认关闭；关闭后不创建新记录。
- 请求体与最终响应体不脱敏、不解析后重写、不格式化后保存。
- 不保存 `Authorization`、`x-api-key`、Cookie 或上游服务商密钥。
- 只额外保存查询所需的非正文元数据。
- 页面允许查看和下载本地数据；不向任何外部地址发送数据。
- 每个本地自然日最终生成一个 `.tar.gz` 压缩包。
- 历史数据不自动删除，只允许用户手动删除单日归档。
- 现有 API 请求体、响应格式、数据库业务数据和路由行为保持不变。

## 3. 方案选择

采用“每日活动目录 + 次日归档”方案。

当天的每次请求使用独立目录保存两个原始 body 文件和一个元数据文件。日期结束后，将整日目录压缩成单一 `tar.gz`。SQLite 只保存索引和统计字段，不保存请求或响应正文。

未采用以下方案：

- 自定义每日二进制日志：文件数量少，但需要专用解析器，恢复和人工检查困难。
- SQLite BLOB：查询容易，但数据库会快速膨胀，并与每日归档形成重复存储。

## 4. 文件与索引结构

数据根目录跟随现有 `MODEL_CENTER_DB_DIR`：

```text
<MODEL_CENTER_DB_DIR>/raw-captures/
├── active/
│   └── 2026-08-26/
│       └── <record-id>/
│           ├── request.body
│           ├── response.body
│           └── metadata.json
├── archives/
│   └── 2026-08-25.tar.gz
└── tmp/
```

未设置 `MODEL_CENTER_DB_DIR` 时，沿用项目当前默认数据目录 `<cwd>/data`。

`record-id` 使用不可预测的 UUID。任何文件访问都由服务端根据已验证 ID 和日期拼接，管理 API 不接受任意文件路径。

### 4.1 metadata.json

元数据包含：

- `id`
- `day`
- `startedAt`
- `completedAt`
- `path`
- `entryProtocol`
- `status`
- `stream`
- `contentType`
- `requestBytes`
- `responseBytes`
- `complete`
- `captureError`

元数据不包含请求 Headers、响应正文摘要、提示词摘要、内容分类或密钥。

### 4.2 SQLite 索引

新增私有索引表：

- `raw_capture_records`：记录 ID、日期、状态、协议、大小、完成状态和活动/归档位置。
- `raw_capture_archives`：记录日期、记录数、原始大小、压缩大小、归档时间和归档状态。

设置继续复用现有 `settings` KV 表，键名为 `raw_capture_enabled`，缺失或非 `1` 时视为关闭。

SQLite 索引可以从活动目录和归档重新核对，不是原始正文的唯一数据源。

## 5. 采集架构与数据流

新增统一 `RawCapture` 包装层，包住四个模型请求入口的完整 POST handler，而不是侵入协议适配器、路由选择或上游转发逻辑。

### 5.1 开关关闭

包装层只读取一次配置并直接调用原 handler：

- 不克隆请求体。
- 不创建目录。
- 不包装响应流。
- 不增加任何网络请求。

### 5.2 开关开启

1. 请求到达模型入口后立即生成记录 ID 和本地日期。
2. 从请求副本读取应用层原始 body 字节并写入 `request.body`；原请求继续交给现有 handler，因此鉴权、JSON 校验和业务执行顺序不变。
3. 原 handler 返回 `Response` 后，记录状态码、内容类型和流式标记。
4. 使用响应观察器包装最终 `Response.body`。客户端收到的每个 `Uint8Array` 块按相同顺序进入有限写入队列，并写入 `response.body`。
5. 响应正常结束时将记录标记为 `complete: true`；客户端取消、响应流报错或采集失败时标记为 `complete: false`，保留已经写入的全部字节。
6. 在记录完成后原子更新 `metadata.json` 和 SQLite 索引。

包装层位于入口最外层，因此鉴权失败、非法 JSON、路由失败、上游错误和成功响应都会被采集。

### 5.3 流式与背压

响应观察器必须保持客户端的字节顺序和现有流取消语义，不使用会让慢速磁盘导致无界内存增长的 `ReadableStream.tee()`。

实现使用单一 reader 和有上限的顺序写入队列：

- 客户端读取仍驱动上游读取。
- 文件写入保持块顺序。
- 队列低于上限时不阻塞客户端。
- 磁盘持续落后并达到上限时，停止该条记录的响应采集、关闭文件并标记 `captureError`；客户端响应继续。
- 客户端取消时向上游传播取消，并等待已排队字节落盘后结束记录。

请求体本身已经由现有 JSON handler 完整读取，因此保存请求副本不会改变当前请求规模特征。任何请求体采集失败都不能阻止原 handler 继续执行。

## 6. 每日归档

日期以服务器本地时区的自然日计算。

归档由以下事件惰性触发：

- 新模型请求进入时进行非阻塞归档检查。
- 打开“原始数据”页面或调用归档列表接口时进行归档检查。
- 用户点击“执行归档检查”时主动触发。

系统不依赖 cron 或常驻调度进程。

归档规则：

1. 只归档早于今天的活动目录。
2. 如果某日仍有未结束记录，则跳过该日。
3. 使用进程内互斥锁防止同一日期并发压缩。
4. 将日期目录写入 `tmp/<day>.<uuid>.tar.gz`。
5. 验证归档能够读取且条目数量与索引一致。
6. 将临时文件原子改名为 `archives/<day>.tar.gz`。
7. 更新 SQLite 归档索引后删除原日期活动目录。

压缩失败时保留原日期目录，记录错误状态，不覆盖已有归档。进程在原子改名前后异常退出时，下次检查会根据活动目录、临时文件、最终归档和 SQLite 索引进行幂等恢复。

为保证“一日一个压缩包”，当前自然日不允许提前压缩。页面上的手动操作名称为“执行归档检查”，只处理已经结束的自然日。

归档内部保持：

```text
<record-id>/request.body
<record-id>/response.body
<record-id>/metadata.json
```

## 7. 后台页面

在“安全”导航组新增：

- “中转风险” `/security-lab`
- “原始数据” `/raw-data`，使用 Lucide `DatabaseBackup`

页面沿用现有 Geist 字体、颜色令牌、Radix/shadcn 组件、明暗主题和响应式后台骨架。

### 7.1 页面头部与采集控制

固定说明：

> 本模块展示中转站能够完整留存用户对话并打包流转的风险；数据仅保存在本机。

采集 Switch 默认关闭。开启前使用 AlertDialog 二次确认。关闭只停止新记录，不删除活动记录或历史归档。

状态区展示：

- 当前采集状态
- 本地保存目录
- 今日记录数
- 今日原始字节数
- 最近一次归档结果
- 最近一次采集错误

### 7.2 中转站数据包视角

展示总记录数、总存储量、覆盖时间和每日归档数量。所有指标只来自元数据，不解析或分类正文。

页面用简明说明指出归档可能包含完整提示词、模型回答、代码上下文和工具结果，服务于视频中的风险演示，但不实现真实外传。

### 7.3 原始记录

桌面端为高密度表格，移动端为摘要卡。字段包括时间、协议、路径、状态、流式状态、请求大小、响应大小和完成状态。

点击记录打开宽 Sheet，分别展示请求和响应：

- 存储文件保持原样。
- 浏览器预览按内容类型尝试 UTF-8 文本显示，不执行 JSON 美化。
- 非文本内容显示十六进制预览。
- 为避免大响应拖垮浏览器，预览有固定字节上限，并明确显示“仅预览前 N 字节”；原始文件下载不截断。
- 活动记录和归档记录都支持下载完整 `request.body`、`response.body`。

读取归档记录时只流式查找目标 tar 条目，不把整日归档解压到磁盘。

### 7.4 每日压缩包

按日期展示归档文件名、记录数量、原始大小、压缩后大小、压缩时间和状态。

支持：

- 下载整日 `.tar.gz`。
- 执行归档检查。
- 经 AlertDialog 确认后删除单日归档。

不提供“一键清空全部”，也不自动删除历史归档。

### 7.5 响应式与无障碍

- 375px 下记录列表改为卡片，详情 Sheet 占满可用宽度。
- 页面本身不产生横向滚动；长正文只在代码预览区域内部滚动。
- 开关、确认框、Sheet 和反馈使用现有 Radix/shadcn 与 Sonner。
- 状态变化通过 `aria-live` 通知辅助技术。
- 控件触控目标至少 44px，并遵守 `prefers-reduced-motion`。

## 8. 管理接口

只新增后台管理接口：

- `GET /api/admin/raw-data/config`
- `PUT /api/admin/raw-data/config`
- `GET /api/admin/raw-data/records`
- `GET /api/admin/raw-data/records/:id`
- `GET /api/admin/raw-data/records/:id/request`
- `GET /api/admin/raw-data/records/:id/response`
- `GET /api/admin/raw-data/archives`
- `POST /api/admin/raw-data/archives`
- `GET /api/admin/raw-data/archives/:day`
- `DELETE /api/admin/raw-data/archives/:day`

列表接口支持服务端分页。正文接口返回原始字节并设置 `Cache-Control: no-store`；下载接口设置安全的 `Content-Disposition`。日期只接受 `YYYY-MM-DD`，记录 ID 只接受 UUID，并且必须通过 SQLite 索引解析真实位置。

不新增外部 API，不改变四个现有模型请求入口的公开协议。

## 9. 内部模块

- `lib/raw-capture/config.ts`：采集配置。
- `lib/raw-capture/capture.ts`：入口包装和采集生命周期。
- `lib/raw-capture/response-observer.ts`：保持字节顺序、背压和取消语义的响应观察器。
- `lib/raw-capture/store.ts`：活动文件、SQLite 索引、查询、下载和删除。
- `lib/raw-capture/archive.ts`：tar.gz 创建、验证和恢复。
- `lib/raw-capture/types.ts`：配置、记录、归档和状态类型。

模块不依赖 Security Lab 改写实现。`/security-lab/v1/messages` 在自身入口采集一次，不因其内部转发或响应改写重复采集。

## 10. 失败处理

- 创建目录、读取请求副本或写盘失败：原模型请求继续，记录内部错误。
- 响应采集失败：停止该条文件写入，客户端流继续，记录标记不完整。
- 客户端中断：保留已经返回给客户端的响应字节并标记不完整。
- 进程异常退出：下次初始化扫描未完成元数据并标记不完整，不删除部分文件。
- 压缩失败：保留活动目录；临时文件用于幂等恢复或安全清理。
- SQLite 写入失败：文件仍保留，下次扫描补建索引。
- 文件缺失或归档损坏：管理 API 返回明确错误，页面显示失败状态，不伪造空内容。
- 删除单日归档时，文件删除与索引更新按可恢复顺序执行；失败时保留可诊断状态。

## 11. 测试计划

### 11.1 纯逻辑与存储测试

- 开关缺失和关闭时不创建文件。
- 开启后请求字节与 `request.body` 逐字节一致，包括空格、字段顺序和 Unicode。
- 最终客户端响应与 `response.body` 逐字节一致。
- 元数据不包含鉴权 Headers 或服务商密钥。
- ID、日期和路径校验阻止目录穿越。
- 进程恢复能够识别不完整记录并补建索引。

### 11.2 流式测试

- SSE 分块顺序和内容完全保持。
- 观察器不会提前抽干慢速客户端流。
- 客户端取消会传播，并保存已发送部分。
- 写入队列达到上限后停止采集但不中断客户端。
- 文件写入错误不会改变网关响应。

### 11.3 归档测试

- 跨日后每个自然日只生成一个 `.tar.gz`。
- 有未结束记录的日期不会被归档。
- 解压后的请求、响应和元数据与源文件逐字节一致。
- 压缩失败不会删除活动目录。
- 原子改名前后模拟崩溃均可幂等恢复。
- 下载和删除只影响目标日期。

### 11.4 路由与 UI 测试

- 四个模型请求入口在开启/关闭状态下行为一致，现有协议零回归。
- 成功、鉴权失败、非法 JSON、路由失败和上游错误均被记录。
- 配置、列表、详情、正文下载、归档和删除 API 返回正确状态。
- 页面开关确认、分页、详情 Sheet、下载、归档检查和删除反馈可用。
- 375x812 与 1440x900 无页面级横向溢出。
- axe 无严重无障碍问题。

### 11.5 交付门槛

E2E 使用独立 `MODEL_CENTER_DB_DIR`，不得接触真实数据库或当前 3000/3100 端口的数据目录。

交付前必须通过：

- `npm test`
- `npm run test:e2e`
- `npm run typecheck`
- `npm run build`

现有网关、Security Lab、API 和数据库测试必须零回归。

## 12. 非目标

- 不解析、脱敏、摘要、分类或搜索对话正文。
- 不存储任何鉴权 Header。
- 不上传、同步或发送原始数据到外部服务。
- 不实现真实的数据售卖、买家、支付或外部数据接收端。
- 不引入 cron、Shell 执行或数据库正文存储。
- 不修改服务商预设、模型目录、模型定价、CC Switch 生成内容或 `public/logos/*`。
