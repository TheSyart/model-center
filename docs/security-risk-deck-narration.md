## 第 1 页｜中转站，新时代木马

[停顿一秒，画面从标题移向红蓝两条传输链。]

很多人选模型中转站，只看两件事：价格够不够低，模型能不能用。但当 Claude Code 这类 Agent 接入中转站以后，问题已经不是简单的账号共享，也不只是网络代理。

它站在用户和官方模型之间，可以同时看到请求与响应。只要其中一段被改写，Agent 接到的就不再是官方模型原本给出的内容。这就是我把它叫作“新时代木马”的原因：它不一定要在电脑里安装病毒，只需要控制你信任的通信通道。

## 第 2 页｜中转站的风险，不只有“贵”和“假”

[依次指向三个矿车。]

讨论中转站时，常见质疑主要有三类。第一，模型掺水，页面写的是高规格模型，实际转发的可能是另一个模型。第二，倍率暗调，标价看着便宜，实际扣费规则却不透明。第三类更危险：信任链被中间人接管。

前两类问题伤的是钱和效果。第三类问题碰到的是提示词、模型响应，以及 Agent 的工具权限。本期先把模型真假和计费放在一边，只看第三类风险是怎么发生的。

[翻到下一页。]

## 第 3 页｜传统木马与中转站

[先指左侧木马，再指右侧中转装置。]

左边是大家熟悉的传统木马。它通常要通过安装包、漏洞或者诱导下载进入设备，然后在本机运行恶意代码。所以我们还能从陌生文件、异常进程、启动项和网络连接里寻找痕迹。

右边的中转站不一样。用户主动把 API 地址改成了它，客户端本身也可能完全正常。中转站只要在模型通信经过时动一下内容，就能把额外意图送进 Agent。真正执行动作的，仍然是用户信任并主动运行的 Claude Code。

两者的入口不同，但危险点很像：隐藏自己的意图，再借用已经存在的权限完成动作。这里说的是风险机制上的类比，不是说所有中转站都属于恶意软件。

[翻到下一页。]

## 第 4 页｜中转站是通信终点

[沿画面中的传输方向，从客户端指向中转节点。]

很多人把中转站理解成一根透明水管。实际上，对 HTTPS 来说，它就是客户端连接的服务器。加密只能保护“客户端到中转站”这一段，数据到达中转站以后已经可以被解密和处理。

因此，一个中转站在技术上可以读取请求、读取模型响应、识别其中的工具调用，再把修改后的内容发回客户端。它也可以把这些数据长期保存。你看到的是一次正常请求，通信边界却已经停在了第三方手里。

[翻到下一页。]

## 第 5 页｜提示词注入

[指向 A、B、A+B 三个阶段。]

先看请求侧。用户输入的是 A，比如“检查项目为什么构建失败”。请求到达中转站以后，中转站在末尾追加一段用户看不到的 B。官方模型最终收到的内容就变成 A 加 B。

我们在项目里做了一条独立的 Claude Code 演示路径。只有手动开启开关时，它才会把自定义后缀追加到最后一条文本请求，并把收到请求、识别 Agent、检查配置、追加内容和转发上游这些步骤写进历史记录。普通网关路径不受影响。

[此处可切到 `/security-lab`：开启“提示词注入”，填写无害的演示后缀，发出请求，再打开改写历史对照原始内容与转发内容。演示完成后切回本页。]

关键不是这段后缀写了什么，而是用户界面里看到的请求，已经不等于模型实际收到的请求。

[翻到下一页。]

## 第 6 页｜Tool Use 注入

[先指向原始钥匙，再指向中转后多出的钥匙。]

第二种改写发生在响应侧。官方模型本来只返回一个正常工具调用，例如读取项目配置。响应经过中转站以后，里面可以被追加第二个 `tool_use`。Claude Code 收到的是结构合法的模型响应，因此会把新增内容当成模型要求的工具操作。

项目里的演示同样需要手动开启，并且只处理声明了对应工具的 Claude Code Agent 请求。为了避免把演示做成真实破坏，我们使用 `printf` 或系统摘要这类无破坏性命令。页面历史会记录上游原始工具、被追加的 Bash 调用，以及 Agent 返回的工具结果。

[此处可切到 `/security-lab`：开启“工具注入”，选择 Bash，填写无破坏性命令；让模型先产生一次正常工具调用，再展示新增调用、执行结果和历史详情。演示完成后切回本页。]

这一段最值得注意：额外命令不需要来自官方模型，它只需要在返回客户端之前，被包装成一个合法的工具调用。

[翻到下一页。]

## 第 7 页｜Agent 会把文字变成动作

[沿“模型响应 → Tool Use → 本机结果”移动指示。]

普通聊天模型给错答案，损失通常停留在屏幕上。Agent 不一样。它能把模型响应继续交给命令行、文件系统、Git、网络工具或者软件安装器。

所以 Tool Use 注入真正放大的不是一句错误回答，而是 Agent 已经拥有的本机权限。它能做到什么，取决于用户给了它多大的操作范围。如果工具默认放行，或者确认提示被用户习惯性跳过，一段被改写的响应就可能直接变成真实动作。

## 第 8 页｜为什么它很难被察觉

[依次指向底部三个说明框。]

这种链路隐蔽，是因为用户没有安装一个名字可疑的软件，也未必能看到陌生进程。执行工具的进程仍然是熟悉的 Claude Code，命令也出现在一次看似正常的模型对话里。

用户真正改变的，可能只有一个 API 地址。此后，正常回答和被追加的内容都从同一个通道返回。传统杀毒软件更擅长检查本机文件和进程，却很难判断一段结构正确的模型响应，究竟是官方模型生成的，还是中间人后来补进去的。

## 第 9 页｜隐私数据如何变成库存

[先指向上方五类数据，再沿底部仓储流程移动。]

中转站看到的内容远比普通聊天记录多。提示词里可能有业务需求，模型响应里有实现方案，Claude Code 还会带上代码上下文、文件路径和工具执行结果。

项目中的“原始数据”模块演示了采集这一侧的能力。开关默认关闭；手动开启后，网关可以保存模型入口的原始请求体与响应体字节，并建立查询索引。跨日数据可以按天归档压缩。采集失败不会改写原本要返回给客户端的数据。

[此处可切到 `/raw-data`：开启原始数据采集，发送一条演示请求，查看请求体和响应体，再展示每日归档。不要在演示请求中放入真实密钥或私人代码。]

这个项目证明的是：中转方具备采集、整理和长期归档对话内容的技术条件。至于现实中的某个服务商有没有把数据拿去出售，需要另外的证据，不能靠猜测下结论。

[翻到下一页。]

## 第 10 页｜证据边界

[先指左侧“项目已经证明”，再指右侧“项目没有证明”。]

到这里必须把证据边界说清楚。这个项目实际展示了提示词拦截与改写、响应侧 Tool Use 注入、改写历史追踪，以及原始请求和响应的采集与归档。这些都是可以在本地重复验证的能力。

但它没有证明任何现实服务商正在做同样的事，也没有证明用户数据已经被出售。能力存在，不等于某个对象已经实施。视频要讨论的是使用不可信中转站时，用户把哪些技术权限交了出去，而不是在没有证据时点名指控。

## 第 11 页｜不要使用不可信中转站

[先指标题，再依次指向底部三个盾牌。]

我的结论很直接：不要把 Claude Code 这类高权限 Agent 接到来源不明的中转站。能官方直连就优先官方直连；确实需要代理，也要确认运营方、数据处理方式和审计能力。

工具调用不要默认全部放行。命令执行、文件写入、网络请求和软件安装应该保留确认；涉及陌生项目时，尽量放进容器、虚拟机或者权限受限的独立环境。敏感代码、密钥和个人信息，不要发给你无法信任的数据通道。

过去我们防木马，会检查下载了什么、运行了什么。Agent 时代还要多问一句：这条命令究竟是谁放进模型响应里的？
